# Meta Lab — первая рабочая версия

Разработка выполняется локально, Railway отложен по запросу пользователя. Открыть: [localhost:8001/meta](http://localhost:8001/meta) (собранное приложение) или [localhost:5173/meta](http://localhost:5173/meta) (Vite). Вход не требуется.

## Возможности

- Паблики, про-сцена и Turbo — отдельные счётчики источника, без смешивания режимов.
- Ранговые срезы 1–8 для пабликов. Варианты без наблюдений отключены в селекторе; прямой запрос пустого среза возвращает пустую статистику, а не замену другим рангом. В проверенном ответе ранг 8 (Титан) имел нулевые счётчики.
- Поиск по имени, теги героя (Carry/Support и другие), атрибут, минимум выборов; сортировка и страницы.
- Winrate, оценка Pickrate, размер выборки; в деталях — точная доля выборов, победы и 95% интервал Wilson. Для про-сцены также доступно сырое число банов.
- Интерактивная карта популярности/результативности: нажатием на точку открываются детали героя. Таблица предоставляет тот же доступ с клавиатуры.
- Три кандидата в пул по нижней границе Wilson среди прошедших фильтры. По умолчанию требуется 1000 выборов для пабликов/Turbo и 20 для про-сцены. Это объяснимый статистический порядок, а не AI или персональный прогноз.
- Пул до пяти героев хранится в localStorage текущего браузера. Это не cookie сессии и не серверный профиль; синхронизации между устройствами пока нет. При недоступном localStorage интерфейс предупреждает, что сохранение не работает.
- Последние восемь известных патчей в API, последние три в интерфейсе; ссылки на официальные изменения. Сбой справочника не блокирует статистику меты.

## API и источник

`GET /api/meta/heroes?mode=pub&bracket=all`

- `mode`: `pub`, `pro`, `turbo`.
- `bracket`: `all` или `1`…`8`. Для pro/turbo допустим только all; другая комбинация возвращает 422.
- `pub/all`: pub_pick/pub_win. Ранг: N_pick/N_win. Pro: pro_pick/pro_win/pro_ban. Turbo: turbo_picks/turbo_wins.
- `/heroStats` загружается на backend, один raw snapshot используется Meta Lab и существующим справочником Dashboard. При смене ранга дата получения остаётся датой исходного snapshot, не текущим временем пересчёта.
- Кэш 120 секунд и общий rate limit существующего приложения. Ошибки/таймауты — через существующий OpenDota adapter; вымышленных fallback-данных в Meta Lab нет.

`GET /api/meta/patches` получает `/constants/patch` и возвращает версии, даты и отдельную дату получения. Справочник не задаёт патч статистики `/heroStats`.

Источник: [OpenDota API](https://docs.opendota.com/). Реальный ответ проверен на 127 героях, всех трёх режимах, рангах 1 и 8 и справочнике патчей.

## Методика

**Winrate:** wins / picks × 100%. При нулевом или неизвестном числе выборов либо неизвестном числе побед — null / «—». Отрицательные, нецелые, boolean-счётчики, дубликаты ID и wins > picks отклоняются как некорректный ответ источника.

**Доля выборов:** picks героя / сумма picks всех героев выбранного среза × 100%. Знаменатель считается до клиентских фильтров. Он не меняется при поиске или фильтрации по тегу, атрибуту и размеру выборки.

**Pickrate\*:** та же доля × 10 — оценка популярности через десять игровых слотов. Это не точная измеренная доля уникальных матчей: исходные счётчики относятся к выборам/игрокам, особенно в ранговых срезах. Число уникальных матчей из них не выводится. При неполных счётчиках picks относительные показатели не рассчитываются; невозможное значение >100% также не публикуется. Точная доля и формула доступны в интерфейсе.

**95% Wilson:** стандартный score-интервал для биномиальной доли, z=1.959963984540054. Сортировка по нижней границе штрафует малые выборки относительно сравнения сырых процентов. Это описательная оценка неопределённости наблюдений, а не гарантия качества героя, доказательство причинности или коррекция всех смещений данных OpenDota.

**Теги:** roles из справочника описывают возможности героя, не фактическую игровую позицию. Среза «Winrate на позиции 5» в этом модуле нет. Универсальный атрибут API имеет код all; фильтр «все атрибуты» использует отдельный код any.

## Что не следует заключать из этих данных

Источник не передаёт точные временные границы heroStats или patch ID выборки. Время получения — не время окончания матчей и не подтверждение свежести агрегации. Последняя версия в справочнике может отставать от игры. UI не объявляет её текущим патчем статистики и не рисует вымышленные изменения Winrate между патчами.

Пока нет исторических snapshot в PostgreSQL, сравнения патчей, позиционной статистики, STRATZ и персонального подбора по матчам пользователя. Эти расширения требуют отдельных источников/измерений. AI Coach, Challenges и другие будущие разделы в этой итерации не разрабатывались.
