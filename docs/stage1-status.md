## Повторная приёмка и подготовка размещения — 14 октября 2026

Сервисы проверены заново, backend перезапущен с изменённым кодом. Предыдущие числа выше сохранены как история первой реализации.

### Исправлено и подготовлено

- Healthcheck исключён из rate limit, чтобы пользовательский трафик не блокировал readiness Railway.
- Отмена, истечение состояния и ошибки проверки Steam возвращают в Dashboard с фиксированным кодом ошибки и повторным входом. Cookies состояния очищаются. Некорректный Unicode state не вызывает 500; дублированные параметры отклоняются.
- Создание аккаунта стало атомарным через `ON CONFLICT DO NOTHING`; настоящая PostgreSQL проверена двумя параллельными входами.
- Cookie deletion сохраняет Secure/HttpOnly/SameSite/Path. Добавлены проверки HTTPS-конфигурации, CORS, Origin, отрицательного ответа/таймаута Steam и отзыва всех сессий при удалении.
- Подготовлена схема одного Railway web-сервиса с frontend/API и отдельной PostgreSQL Railway. Добавлены multi-stage Dockerfile, корневой railway.json, pre-deploy migration, образец переменных и инструкция `docs/deployment-railway.md`. Supabase для этой схемы не требуется и не подключался.
- Backend умеет опционально раздавать собранный frontend: SPA fallback не подменяет отсутствующие API/assets, скрытые файлы и traversal отклоняются, HTML и assets получают разную cache policy. При проверке на Windows обнаружена нормализация StaticFiles в обратные слеши; исправлено до сравнения API/assets путей.
- В production добавлены HSTS и проверка FRONTEND_URL в CORS allowlist. Режим `CLIENT_IP_SOURCE=railway` использует один валидный X-Real-IP только при явно настроенной границе Railway HTTP ingress. По умолчанию заголовки клиента игнорируются.
- Добавлены preview-скрипт и Steam redirect probe; локальные запросы probe не уходят во внешний HTTP proxy. Скрипт не авторизует пользователя и не печатает state/cookies.
- GitHub CI дополнен отдельной подготовленной проверкой Docker images, миграции и HTTP health/static endpoint. Сам GitHub CI в этой сессии не выполнялся.
